# Project critique: usp-mp

Review of a small Python client for the *Mein Postkorb* SOAP/REST service. First written at commit `9085f5f`, updated against `3c10a6f`. The core design is sound (`adapter` → `mail`, `Mailbox → Delivery → Attachment`), but it is early-stage code with real bugs, a key-handling weakness, and no tests.

Status markers: **[fixed]** resolved since the first review, **[open]** still applies. Since 2026-11-17, findings are also checked against the demo (TEST) service with `tests/test_demo.py` (needs your own client certificate; see README). Other findings come from reading the code, the bundled WSDL/XSD schemas and certificate, and the vendor HowTo. Items marked *verify* should be confirmed empirically.

The plan for fixing every open item is in [fix-plan.md](fix-plan.md); its "Facts checked while planning" section is the evidence behind the schema-based notes below.

**Progress:** fixed so far: B1, B3, B7, B9, B10 (new), the private-key handling (S1), attachment download through the session (S2), the command-line password (S3, with a warning), the sanitising utility (D6), the test harness, and the packaging/hygiene items marked below. Phase 0 and Phase 1 of [fix-plan.md](fix-plan.md) are done; everything else is still open.

## Bugs

1. **[fixed] CLI never returned an exit status.** `SystemExit(main())` built the exception without raising it. Now `raise SystemExit(main())` (`src/usp_mp/cli.py:92`), and the `uspmp` console script uses `sys.exit(main())`.
2. **[fixed] Results silently truncated at 100.** `deliveries(all=True)` now pages 1000 at a time until `HitCount` is reached (or an empty page), collecting all IDs before yielding and dropping IDs repeated by mid-paging arrivals. `deliveries(all=False)` asks for 1000 and logs a warning when `HitCount` is larger. New `limit=` keyword. Tested against the fake (2500 deliveries, deletion during iteration, inconsistent `HitCount`) and live with a page size of 3. Original finding: `mail.py:42,45` hardcode `Limit=100` (and `Start=0`) in both selectors. `all=True` reads as "everything", but only the first 100 are returned. Per the schema, `Limit` may be 1–1000 and `HitCount` is the total. `AllDeliveriesType` can be paged with `Paging(Start, Limit)`, but `NewDeliveriesOnlyType` takes only `Limit` and **cannot be paged**, so new-only queries can at best raise the limit to 1000 and warn when `HitCount` is larger. When paging, collect all IDs before yielding: closing or deleting deliveries mid-iteration would otherwise shift server-side offsets and skip messages. **Confirmed on the demo service:** `Start`/`Limit` paging reassembles the full list, `HitCount` is always the total, and a new-only query with `Limit=1` returns `HitCount=3` but one ID.
3. **[fixed] Checksum handling had dead code; the logic itself was correct.** Now: an explicit `SHA256`/`SHA512` → hashlib mapping (`Attachment.CHECKSUM_ALGORITHMS`), a clear `ValueError` for anything else, and `hmac.compare_digest` for the comparison. Original finding: `hashlib.new()` raises `ValueError` for an unknown algorithm; it never returns `None`, so the `if hash is None` branch (`mail.py:87`) is dead code and its `KeyError` unreachable. The earlier *verify* concerns are mostly answered by the schema: `AlgorithmID` is an enumeration of `SHA256` or `SHA512`, both accepted by `hashlib.new()` (tested on 3.11 and 3.14), and `Value` is `base64Binary`, which zeep decodes to `bytes`, so comparing it to `hash.digest()` is right. **Verified on the demo service:** all attachments use `SHA512`, values arrive as `bytes`, every download verifies, and the declared `Size` matches.
4. **[fixed] `raise_on_error` was loosely typed and brittle.** It is now a module-level function: `getattr(response, "Error", None)` and, if set, `ApiError(code, message, operation)`. The schema guarantees both fields whenever `Error` is present.
5. **[fixed] `Mailbox.deliveries()` was a generator holding a live connection.** `Mailbox` is now a mandatory context manager that owns one connection for the whole `with` block and closes it deterministically, also on an exception or an early `break`. Objects can't silently use a closed connection any more: `content()`, `close()` and `delete()` raise `RuntimeError` after the block. Still inherent to the API: each `Delivery(...)` does a blocking `GetDelivery`, so N deliveries mean N+1 round trips (fix-plan 3.3; documented in the howto, since the service has no batch call).
6. **[won't fix] Builtin shadowing.** The `hash` local is gone (fixed with B3). `all` (parameter of `Mailbox.deliveries`) still shadows the builtin, but the function never calls `all()`, and renaming public API isn't worth the breakage. Maintainer decision, 2026-11-17.
7. **[fixed] CLI argument handling.** `--client-certificate` is required and must exist; an unset `ENV:` variable, an unreadable password file and a bad `--download` directory are argparse usage errors (exit 2). Runtime errors print one `uspmp: error: …` line and exit 1 (`--debug` shows the traceback); Ctrl-C exits 130. `main()` takes an optional `argv` list.
8. **[fixed] `--save` directory naming was unstable.** Directories are now named by delivery ID (`<download>/<delivery-id>/<index>_<name>`), created with `exist_ok=True`, so re-runs work and a directory always holds the same delivery. Files are written atomically (`usp_mp.util.write_atomic`: `.part` file, fsync, rename), so a crash never leaves a truncated file that looks complete.
9. **[fixed] Filename sanitising quirks.** Now `usp_mp.util.sanitize_filename`: every run of unsafe characters (including existing underscores) becomes one `_`, with none at the ends; accents are folded to ASCII; the stem is capped at 100 characters, with a fallback name if it ends up empty; and the original extension is kept when it matches the MIME type. A dot inside a name (`v1.2 final`) is no longer mistaken for an extension. `usp_mp.util.unique_path` avoids collisions, and the howto example uses it. The CLI already prefixes an index.
10. **[fixed] `usp_mp.mail` could not be imported on Python < 3.14.** New finding. `Mailbox.deliveries()` is annotated `-> Iterator[Delivery]` before `Delivery` is defined; only 3.14's deferred annotation evaluation made that work, so the `>=3.14` pin was hiding a `NameError` on 3.11–3.13. Fixed with `from __future__ import annotations` in `mail.py`; import verified on 3.11–3.14.
11. **[verified, no action] Query requests differ from the documented form.** New finding while writing the request-shape tests. The vendor HowTo sends `<aa:AllDeliveries>` / `<aa:NewDeliveriesOnly>`, which are substitution-group members of `aa:Query`. zeep cannot emit substitution elements (the same limitation behind the `strict=False` workaround below) and sends `<aa:Query xsi:type="aa:AllDeliveriesType">` instead, even when given the `AllDeliveries` element. That is schema-valid, because `Query` itself is not abstract (only its type is), and the client has presumably always worked this way. But it is not what the vendor documents, so a stricter server-side validator could reject it. `tests/test_demo.py::test_query_accepted` confirms acceptance once run with a certificate; if it ever fails, the fix is to build the `QueryDeliveriesRequest` body by hand (e.g. zeep's `xsd.AnyObject` or a raw lxml element). **Verified on the demo service:** it accepts the `xsi:type` form, and it does validate requests: `Limit=0` and `Limit=1001` are rejected with a `Validation error` fault.
12. **[open, *verify on production*] New-only `Limit` applies before the unread filter.** Found on the demo service: `NewDeliveriesOnly(Limit=n)` takes the first *n* deliveries of the whole mailbox, then returns the unread ones among them; `HitCount` is still the true number of unread deliveries. On the demo (new ones at positions 1, 5 and 10), `Limit` 1–4 returns one ID, 5–9 two, 10+ all three. If production behaves the same, a mailbox with more than 1000 deliveries in total can hide unread ones beyond position 1000 from new-only queries, and closing processed deliveries won't bring them into view (only deleting would). The library's truncation warning compares against `HitCount`, so it fires in that case. Checking production needs only read-only `QueryDeliveries` calls; `tests/test_demo.py::test_new_only_limit_applies_before_unread_filter` documents the demo behaviour.

## Security

- **[fixed] Private key written to disk in plaintext.** `ConnectionContext.__enter__` used to write the decrypted key to `NamedTemporaryFile(delete=False)` for the whole connection, leaking it on a crash or a failure inside `__enter__`. Now `USP_MP_Adapter.build_ssl_context` builds one `SSLContext` per adapter: the key is written only **encrypted** with a random one-time password, into a 0700 temp dir that is removed right after `load_cert_chain` (also on error), and the context is mounted on the session via `SSLContextAdapter`. The plaintext `key_pem` attribute is gone. Python's `ssl` cannot load keys from memory, so this is the closest equivalent. Covered by `tests/test_adapter_tls.py` (mutual TLS against a local server, 3.11–3.14).
- **[fixed] `download_attachment` bypassed the session.** It now uses `self.session.get(..., timeout=TIMEOUT)`, so it gets the client certificate from the mounted context, the User-Agent, connection reuse, and a timeout.
- **[fixed] Password on the command line** (`--client-password`) is visible in `ps`. Added `--client-password-file`, and a literal non-empty password now prints a warning. The literal form stays supported (maintainer decision, 2026-11-17).
- **[fixed] `strict=False` for all calls** silently lost the `CorporateBody` (and the elements after it) of `Sender` and `Receiver`, because zeep doesn't resolve the `p:Person` XSD substitution group. Fixed by patching the bundled schema: every `ref="p:Person"` is replaced with an explicit choice of `PhysicalPerson`/`CorporateBody`, its only substitution-group members, so the choice is equivalent (documented in `src/usp_mp/wsdl/PATCHES.md`). All demo responses now parse completely, with `strict=True` as well. The library deliberately stays on `strict=False`, so a future unknown element can't block mail retrieval; instead `Delivery` logs a warning naming any unparsed elements, and `tests/test_demo.py` parses every live response strictly as a schema-drift alarm. Offline, `tests/test_wsdl.py` parses a recorded demo response and guards the patch against vendor updates.

## Design

All fixed.

- **[fixed] Zeep client built twice.** The adapter now parses the WSDL once (`USP_MP_Adapter.load_wsdl`), and every connection's zeep client reuses that `Document` with its own transport and session. Previously each mailbox parsed it twice (about 20 ms each).
- **[fixed] `self.service = None` then `assert connection.service` everywhere.** `ConnectionContext.service` is now a property that is always set and raises `RuntimeError` once the connection is closed; the asserts are gone.
- **[fixed] `types = ParamTypes()` was a class attribute mutated per instance via `setattr`.** Now each adapter has its own frozen `QueryTypes` instance resolved from its own parsed WSDL; nothing is shared between adapters. The adapter and `Mailbox` are documented as not thread-safe (one per thread).
- **[fixed] Zeep objects leaked out** via `Delivery.delivery` and `Attachment.attachment`, with no accessors for sender, receiver and most metadata. Now: `Delivery.sender`/`receiver` return a typed `Contact` (organisation or person, with identification), plus `gz`, `delivery_quality`, `app_delivery_id`, `zs_delivery_id`, `delivery_service`, `origin`; `Attachment.size`/`document_class`; and `raw` on both for anything else. The old attributes remain. The CLI shows the sender in its listing.
- **[fixed] Error handling.** New `usp_mp.errors`: `UspMpError` as the base, with `CertificateError` (an unreadable `.p12`, a wrong password or no key, chained `from` the cause), `ApiError` (`.code`, `.message`, `.operation`), `ChecksumError` and `MailboxStateError`. `ApiError`/`ChecksumError` are still `ValueError`s and `MailboxStateError` a `RuntimeError`, for compatibility. `Mailbox.__init__` no longer wraps everything in `RuntimeError`. The CLI prints `UspMpError` messages as-is and prefixes anything else with its type.
- **[fixed] Sanitising belongs in a utility**: moved to `usp_mp.util`; `Attachment.sanitize_fname` remains as a compatibility alias.

## Packaging and repo hygiene

- **[fixed] `requires-python`** lowered from `>=3.14` to `>=3.11` (see bug 10 for the code change this needed).
- **[fixed] Console script.** `uspmp.py` moved to `src/usp_mp/cli.py` and exposed as `[project.scripts] uspmp = "usp_mp.cli:main"`; `docs/howto.md` updated. `python uspmp.py` no longer exists.
- **[fixed] README "Installation"** section is filled in. It uses a `<repository-url>` placeholder on purpose, because the origin remote is private.
- **[fixed] `.gitignore`** rewritten: stray `:` and merged pattern removed; the blanket `.*` rule (which would have hidden e.g. `.github/`) and unused template sections dropped; `.jj/` added; `*.cer` no longer blocks the bundled CA cert (`!src/usp_mp/certs/*.cer`).
- **[fixed] Typos and naming** ("ist not a directory", "rom private_key", "instanciate", "Mein Postfach", "Unternehmer-Service-Portal", "Postbevollmaechtigter", "return" → "returns", "meta data").
- **[fixed]** `description = "Add your description here"` in `pyproject.toml` was the template placeholder. Now a real description, plus `keywords` and `classifiers` (Python 3.11–3.14, typed, beta). No `[project.urls]`, since the repository is private.
- **[fixed]** No licence file. Now BSD 3-Clause: `LICENSE`, plus `license = "BSD-3-Clause"` and `license-files` in `pyproject.toml` (PEP 639, so `setuptools>=77`); the built wheel and sdist both carry it.
- **[open]** `brz_ca.cer` is pinned and shipped with no note on source, fingerprint or expiry. It is `CN=BRZ-StammCA-2-02, O=Bundesrechenzentrum GmbH`, valid until **2038-01-12**, so rotation is not urgent; still document its details, origin, and how to refresh it.
- **[won't fix]** Version `1.0.YYYYMMDD` mixes semver and CalVer and is hand-edited (now `1.0.20261117`; the CHANGELOG lists breaking changes explicitly). Keeping the scheme is a maintainer decision (2026-11-17); remember to bump `__version__` and rename the CHANGELOG's *Unreleased* heading when releasing.
- **[fixed]** The library had no `logging`. Now `usp_mp.adapter` and `usp_mp.mail` log at DEBUG (endpoint, certificate validity, connections, queries with paging and `HitCount`, fetches, download sizes), INFO (close/delete) and WARNING (new-only truncation, a client certificate expiring within 30 days or already expired, unparsed response elements), never secrets or contents. The CLI shows warnings as `uspmp: warning: …`, and with `--debug` the library's debug output as well. While doing this, a latent bug was found and fixed: the old `--debug` setup used `logging.config.dictConfig`, which by default disables already-created loggers, so `usp_mp.mail`'s warnings would have been swallowed exactly in debug mode.
- **[open]** `docs/` contains the vendor PDF, a `.txt` copy of it, and a zip. Useful reference, but redistribution rights are unclear; consider linking instead. They are not in the sdist or wheel (checked with a build), so this only concerns the repository.
- **[open]** The sdist includes `tests/test_*.py` (setuptools' default) but not `tests/conftest.py` or `tests/fakes.py`, so the tests cannot run from an unpacked sdist. New finding from a test build. Either include the whole `tests/` directory (`MANIFEST.in`: `graft tests`, then `global-exclude __pycache__ *.py[cod]`) or exclude it entirely.

## Testing

**[fixed]** The Phase 0 harness exists; see README "Development" for how to run it. It passes on 3.11–3.14 with no certificate:

- `tests/fakes.py` + `conftest.py`: an in-memory fake of the service. Responses are real zeep objects built from the bundled WSDL, so fakes cannot use fields the schema lacks. Error codes and HTTP 400 follow the vendor HowTo.
- `test_mail.py`, `test_cli.py`: current behaviour of `Mailbox`/`Delivery`/`Attachment` and the CLI (querying, metadata, close/delete, checksum verification, API errors, filename sanitising, `--save`, `ENV:` passwords).
- `test_wsdl.py`: the bundled WSDL loads and produces the expected request XML (see B11). `test_import.py`: import smoke test (guards B10). `test_adapter_tls.py`: client-certificate handling.
- Known open bugs are `xfail(strict=True)` tests: B2 (paging), B7 (missing certificate), B8 (`--save` rerun), B9 (underscores). Fixing one makes its test fail until the marker is removed.
- `test_demo.py`: demo-service tests, plus strict `xfail` tests for S4. They cover connection, querying and paging, metadata, downloads and checksums, error responses, close/delete and the CLI, and they compare the fixed demo data against the vendor HowTo's documented IDs and a golden snapshot (`tests/data/demo_snapshot.json`). Skipped unless the person running them provides a client certificate and password (`--p12=…`/`USP_MP_P12` and a password file or value); nothing of the kind is in the repository. First run on 2026-11-17: all pass.

Still missing tests for the fixes themselves (pagination, exception hierarchy, etc.); those come with each phase.

## Strengths

- Small, clear surface that maps to the domain.
- WSDL and CA bundled, so no dependency on the portal's `?wsdl`; comments explain why.
- Checksum verification on by default; the CLI only marks deliveries read after saving them.
- Docs exist and are mostly accurate, including the demo-vs-prod caveat; installation is now documented.
- Type hints and `py.typed` shipped; the CLI is a proper installed command.
